Q1. Consider the relation R(A,B,C,D,E,F) and F= {A → BC, AC → DEF, F → AB}. List candidate keys and find minimal cover.[cite: 30]
▼
Teacher's Solution Fall 2023-2024
i. List all of the candidate keys [4 Marks]
  • A+ = A
  • Using A → BC = ABC
  • Using AC → DEF = ABCDEF
  • F+ = F
  • Using F → AB = FAB
  • Using A → BC = FABC
  • Using AC → DEF = FABCDE
  • Candidate Keys are A and F.[cite: 30]
ii. Give the minimal cover for F [6 Marks]
  • A → BC:
    Case 1: B can be extraneous?
    F' = {A → C, AC → DEF, F → AB}
    A+ on F' = ACDEFB. It contains attribute B, So B is extraneous.
    F = {A → C, AC → DEF, F → AB}[cite: 30]
  • AC → DEF:
    Case 1.1: A is extraneous?
    C+ = C does not contain attribute DEF, So A is not Extraneous.
    Case 1.2: C is extraneous?
    A+ = ADEFCB does contain attribute DEF, So C is Extraneous.
    F = {A → C, A → DEF, F → AB}[cite: 30]
  • A → DEF:
    Case 1.3: D is extranoeus?
    F' = {A → C, A → EF, F → AB}
    A+ on F' = CEFAB. Does not contain D, Hence D is not extra.
    Case 1.4: E is extraneous?
    F' = {A → C, A → DF, F → AB}
    A+ on F' = CDFAB. Does not contain E, E is not extra.
    Case 1.5: F is extraneous?
    F' = {A → C, A → DE, F → AB}
    A+ on F' = CDEAB. Does not contain F, F is not extra.[cite: 30]
  • F → AB:
    Case 1.6: A is extraneous?
    F' = {A → C, A → DEF, F → B}
    F+ on F' = FB. Does not contain A, A is not extra.
    Case 1.7: B is extraneous?
    F' = {A → C, A → DEF, F → A}
    F+ on F' = FACDEF. Does not contain B, B is not extra.
    Fc = {A → C, A → DEF, F → AB}. All left hand side are unique and no extraneous attribute in FD.[cite: 30]
  • A → BC:
    Case 2: C can be extraneous
    F' = {A → B, AC → DEF, F → AB}
    A+ on F' = AB. Does not contain attribute C, C is not extra.
    So Final minimal cover Fc = {A → CDEF, F → AB}[cite: 30]
Q2. Given R(A,B,C,D,E) and dependencies P = {A → B, AB → C, D → AC, D → E}, Q = {A → BC, D → AE}. Check whether P and Q are equivalent?[cite: 30]
▼
Teacher's Solution Fall 2023-2024
To check P ⊆ Q

Let's find closure of the left side of each FD of P using FD Q.

  1. A+ = ABC (using A → BC)
  2. AB+ = ABC (using A → BC)
  3. D+ = DAEBC (using D → AE and A → BC)
  4. D+ = DAEBC (using D → AE and A → BC)

Now compare closure of each A, AB, D and D calculated using FD Q with the right-hand side of FD P. Closure of each A, AB, D and D has all the attributes which are on the right-hand side of each FD of P. Hence, we can say P is a subset of Q.[cite: 30]

To check Q ⊆ P

Using definition of equivalence of FD set, let us determine the right-hand side of the FD set of Q using FD set P.

Given P = {A → B, AB → C, D → AC, D → E} and Q = {A → BC, D → AE}

Let us find closure of the left side of each FD of Q using FD P.

  1. A+ = ABC (using A → B and AB → C)
  2. D+ = DACEB (using D → AC, D → E, and A → B)

Now compare closure of each A, D calculated using FD P with the right-hand side of FD Q. Closure of each A and D has all the attributes which are on the right-hand side of each FD of Q. Q is a subset of P.[cite: 30]

Hence P is equivalent to Q.[cite: 30]

Q3. R=(ABCD), F={AB → C, B → D, C → A}. Find candidate keys, check BCNF, decompose, check dependency preservation.[cite: 40]
▼
Teacher's SolutionFall 2024-2025
Step 1: Compute Attribute Closure

A+ = A, B+ = BD, C+ = AC, D+ = D
AB+ = ABCD, BC+ = ABCD
So our candidate keys are AB and BC.[cite: 40]

Step 2: Check BCNF Violation
  • AB → C: Does this violate BCNF, i.e. is AB a key for R? The answer is yes, so no violation.
  • B → D: Does this violate BCNF? Yes, because B is not a key. So we create 2 relations: (BD) and (ABC).
Step 3: Decompose
  • For (BD) the candidate key is B. The only FD that applies here is B → D so it is in BCNF.
  • For (ABC), the candidate keys are AB and BC. The first FD applies, AB → C and AB is a key so it is in BCNF. The second FD doesn't apply (there is no D in it), and the third FD does apply (C → A). Is C a key no, so we need to decompose by creating a new relation schema made up of the FD, and pulling out the right side of the FD from the original.
  • Final state: (BD)(CA)(BC). BD is still in BCNF as before. CA has C as the candidate key, and the only FD that applies is C → A. It is in BCNF. BC has BC as the candidate key, and no FDs apply, so it is in BCNF.

Our final decomposition is: (BD)(CA)(BC).[cite: 40]

Step 4: Dependency Preservation

This BCNF decomposition did not preserve dependencies. We have lost the ability to check AB → C without doing a join. In this case a 3NF decomposition would be better served, which was back at: (BD)(ABC).[cite: 40]

Candidate Key r = {AD, BCD}.[cite: 41]

Q6. R(StudentID, CourseID, Hobby, Instructor...) MVD: StudentID →→ Hobby. Determine candidate keys, explain 4NF violation and decompose.[cite: 36]
▼
AI-Generated SolutionWinter 2025-2026
Step 1: Determine Candidate Keys

Looking at the FDs, CourseID determines all course-related attributes (Instructor, InstructorOffice, CourseDept). StudentID and CourseID must be paired to uniquely identify an enrollment, but since a student can have multiple hobbies independently of courses, we must include Hobby in the key.

(StudentID, CourseID, Hobby)+ = {StudentID, CourseID, Hobby, Instructor, InstructorOffice, CourseDept}.

Candidate Key: {StudentID, CourseID, Hobby}.

Step 2: Check 4NF Violation

A relation violates 4NF if it contains a non-trivial Multivalued Dependency (MVD) X →→ Y where X is NOT a superkey.
We are given the MVD: StudentID →→ Hobby.

Since StudentID alone is NOT a superkey (it cannot determine CourseID or Instructor), this MVD causes massive data redundancy (every hobby a student has is repeated for every course they take). Thus, it violates 4NF.

Step 3: Decompose to 4NF

We isolate the independent multivalued attribute into its own table, linking it by the determinant.

  • R1(StudentID, Hobby) — Key: {StudentID, Hobby}. In 4NF.
  • R2(StudentID, CourseID, Instructor, InstructorOffice, CourseDept) — This removes the MVD, making R2 in 4NF (though technically it violates BCNF and needs further normalization to fully normalize). For the 4NF requirement, the primary MVD violation is removed.
Q7. R=(B,C,D,E,F,G) with D → G, F → B, FD → E, B → C. Find all possible super keys and minimal super keys. Find implied FDs applying axiom rules.[cite: 38]
▼
AI-Generated SolutionFall Inter 2023-2024
Step 1: Find Minimal Super Keys (Candidate Keys)

Identify attributes that never appear on the right side of any FD: F and D.

Calculate closure of (FD)+:

  • From D → G: {F, D, G}
  • From F → B: {F, D, G, B}
  • From B → C: {F, D, G, B, C}
  • From FD → E: {F, D, G, B, C, E}

Since (FD)+ contains all attributes of R, and neither F nor D alone can determine all attributes, FD is the sole minimal super key (Candidate Key).

Step 2: Find Possible Super Keys

A super key is any combination of attributes that contains the minimal super key. Since FD is the minimal key, any set containing {F, D} is a super key. Examples: {F,D}, {F,D,A}, {F,D,B}, {F,D,B,C}, etc. (Total of 24 = 16 super keys since 4 attributes are remaining).

Step 3: Implied FDs using Axioms
  • Transitivity Rule: If F → B and B → C, then F → C.
  • Augmentation Rule: If D → G, then adding F to both sides gives FD → FG.
  • Union Rule: Since F → B and F → C (from step 1), then F → BC.
  • Decomposition: Since FD → E, we know FD uniquely identifies E.

Q14. Extendible hashing on search key values 2,3,5,7,11,17,19,23,29,31. Hash function h(x) = x mod 8 and buckets can hold 2 records.[cite: 35]
▼
AI-Generated SolutionWinter 2023-2024
Step 1: Calculate Hash Values (Binary)

h(x) = x mod 8, which yields a 3-bit binary value.

2 -> 010 17 -> 001 3 -> 011 19 -> 011 5 -> 101 23 -> 111 7 -> 111 29 -> 101 11 -> 011 31 -> 111
Step 2: Insert into Buckets (Max size = 2)

Start with Global Depth (GD) = 1, Local Depth (LD) = 1.
Insert 2 (010) → Bucket 0
Insert 3 (011) → Bucket 1
Insert 5 (101) → Bucket 1
Insert 7 (111) → Bucket 1 OVERFLOWS (contains 3, 5).

Step 3: Directory Expansion and Splitting

GD increases to 2. Directory entries: 00, 01, 10, 11. LD of Bucket 1 increases to 2.
Bucket 1 splits. Values ending in '01' go to one bucket, '11' to another.
5 (101) → Bucket 01.
3 (011) → Bucket 11.
7 (111) → Bucket 11.

Step 4: Continue Insertion

Insert 11 (011) → Bucket 11 OVERFLOWS (contains 3, 7).
GD increases to 3. Directory entries: 000, 001, 010, 011, 100, 101, 110, 111.
Bucket 11 splits based on 3rd bit. LD increases to 3.
3 (011) → Bucket 011.
11 (011) → Bucket 011.
7 (111) → Bucket 111.

Step 5: Final Overflows

Insert 17 (001) → Bucket 001.
Insert 19 (011) → Bucket 011 OVERFLOWS (contains 3, 11). Since LD=3 and GD=3, GD must increase to 4 (directory doubles to 16 entries). LD of the split bucket becomes 4, allowing the collision between 3, 11, and 19 to resolve depending on the 4th bit (requiring h(x) = x mod 16, but if restricted to mod 8, an overflow chain/bucket must be used as they produce identical hash keys). Assuming a pure mod 8 function, the bucket 011 will permanently overflow, requiring an overflow chain block.

Conflicts occur when two operations from different transactions access the same item, and at least one is a write.[cite: 41]

  • Conflict 1: T1 writes A at t4, then T2 reads A at t5 (W-R conflict).[cite: 41]
  • Conflict 2: T1 writes A at t4, then T2 writes A at t7 (W-W conflict).[cite: 41]
  • Conflict 3: T2 writes B at t10, T1 reads B at t12 (W-R conflict).[cite: 41]
  • Conflict 4: T2 writes B at t10, T1 writes B at t14 (W-W conflict).[cite: 41]

(iii) ACID Properties at Risk
  • Atomicity: T1 and T2 both eventually commit, so atomicity is maintained.[cite: 41]
