4.1 Knowledge Representation & Reasoning (KRR)

Topic 4.1
KB-Agent Cycle: Perceive → TELL(KB, Percept) → Infer → ASK(KB, Action) → Act
5 Types of Knowledge Core Meaning Slide Example
1. Declarative "Know What" — facts, concepts, static truths Student(Ravi), Chennai is in TN
2. Procedural "Know How" — step-by-step rules, algorithms Area of circle: obtain r, compute πr2
3. Meta-Knowledge "Knowledge about knowledge" — reliability, priority "Apply Rule 1 before Rule 2"
4. Heuristic "Rule of Thumb" — experience-based, not guaranteed "Control the center of the board in chess"
5. Structural Relationships: IS-A, PART-OF, BELONG-TO Car IS-A Vehicle; Engine PART-OF Car

Two Levels of AI System

  • Knowledge Level: What the agent knows (e.g., Gold is present, Pit nearby).
  • Implementation Level: How it is stored (arrays, graphs, logic clauses).

Knowledge Base (KB) vs Database (DB)

  • KB: Explicit rules + facts, experts update, main-memory based, infers new facts.
  • DB: Mostly passive facts, clerks update, disk-based, only retrieves.

4.3 Equivalence Laws, Validity & Rules of Inference

50% PYQ Weight
Law / Rule Name Formula / Equivalence Key Idea / Memory Trick
Implication Elimination (α → β) ≡ (¬α ∨ β) Step 1 of every CNF conversion & equivalence proof
Contrapositive Law (α → β) ≡ (¬β → ¬α) Flip and negate both sides ("Not sunny → Umbrella" ≡ "No umbrella → Sunny")
Biconditional Elim. (α ↔ β) ≡ (α → β) ∧ (β → α) Two-way implication
De Morgan's Laws ¬(α ∧ β) ≡ (¬α ∨ ¬β)
¬(α ∨ β) ≡ (¬α ∧ ¬β)		 Push negation inside brackets and flip ∧ / ∨
Distributive Laws α ∨ (β ∧ γ) ≡ (α ∨ β) ∧ (α ∨ γ)
α ∧ (β ∨ γ) ≡ (α ∧ β) ∨ (α ∧ γ)		 Top row converts to CNF (AND of ORs); bottom row converts to DNF (OR of ANDs)
Modus Ponens (MP) P → Q,   P   ∴   Q Confirm P → Get Q (Affirming the antecedent)
Modus Tollens (MT) P → Q,   ¬Q   ∴   ¬P Deny Q → Reject P (Denying the consequent)
Hypothetical Syllogism P → Q,   Q → R   ∴   P → R Chain Rule of implications
Disjunctive Syllogism P ∨ Q,   ¬P   ∴   Q Unit Resolution: OR + NOT one → keep the other
Resolution Rule P ∨ Q,   ¬P ∨ R   ∴   Q ∨ R Cancel complementary literals (P and ¬P) and join the rest

Valid vs Satisfiable vs Unsatisfiable

  • Valid (Tautology): True in all models (e.g., P ∨ ¬P).
  • Satisfiable: True in at least one model (e.g., P ∨ Q).
  • Unsatisfiable (Contradiction): True in no models (P ∧ ¬P).
  • Theorems: KB ⊨ α iff (KB → α) is Valid, iff (KB ∧ ¬α) is Unsatisfiable.

Cloned PYQ Puzzle: 3 Chests / 3 Toppers

  • Clues: Box 1 / Anjali: ¬B1 | Box 2 / Braian: ¬B2 | Box 3 / Chenna: B2.
  • Rule: Exactly 1 box has treasure & only 1 clue is True.
  • Winner: Row (B1=T, B2=F, B3=F) makes Clue 2 (¬B2) True and Clues 1 & 3 False → Chest 1 / Anjali!

4.4 & 4.5 First-Order Logic (FOL) Architecture & Guaranteed PYQ Translations

100% Exam Probability

Propositional Logic (PL) vs First-Order Logic (FOL)

  • Ontology: PL represents atomic facts (P, Q); FOL models Objects, Properties, Relations, Functions.
  • Terms (Return Objects): Constants (John, Mumbai), Variables (x, y), Functions (FatherOf(Mary)). A term with no variables is a Ground Term.
  • Sentences / WFF (Return True/False): Predicates (Brother(x,y)), Connectives, Quantifiers. A WFF has all variables bound by quantifiers (no free variables).
  • Complexity: PL inference is NP-Complete (DPLL, GSAT); FOL inference is Semi-decidable.

Golden Quantifier Rules & Duality

  • Universal (∀x) pairs with →: ∀x (Student(x) → Smart(x)). Trap: ∀x (Student(x) ∧ Smart(x)) means everyone in the world is a student!
  • Existential (∃x) pairs with ∧: ∃x (Student(x) ∧ Smart(x)). Trap: ∃x (Student(x) → Smart(x)) is trivially true for any non-student!
  • Mixed Quantifier Order Matters: ∀x ∃y Likes(x,y) (Everyone likes someone) ≠ ∃y ∀x Likes(x,y) (Someone is liked by everyone).
  • Quantifier De Morgan Laws: ∀x ¬P(x) ≡ ¬∃x P(x)  |  ¬∀x P(x) ≡ ∃x ¬P(x)  |  ∃x P(x) ≡ ¬∀x ¬P(x).
Pattern Category English Sentence (From Lecture Slides & Past Papers B1, E1, E2, D1, D2) First-Order Logic (FOL) & Clause Form (CNF)
PYQ Clone #1: Universal 2-Object Comparison "Any house in Parson/Bhopal costs less than any apartment in Chennai/Pune."
(Also: "Any book in the library is more expensive than any magazine in the store.")		 FOL: ∀x ∀y ((House(x) ∧ In(x, Parson) ∧ Apt(y) ∧ In(y, Chennai)) → LessCost(x, y))
CNF: ¬House(x) ∨ ¬In(x, Parson) ∨ ¬Apt(y) ∨ ¬In(y, Chennai) ∨ LessCost(x, y)
PYQ Clone #2: Conjunction in Consequent "Any electric car is more efficient and produces less pollution than a gasoline car."
(Also: "Any 3-star washing machine costs less but consumes more power than a 5-star...")		 FOL: ∀x ∀y ((EC(x) ∧ GC(y)) → (Efficient(x, y) ∧ LessPollution(x, y)))
CNF: (¬EC(x) ∨ ¬GC(y) ∨ Efficient(x, y)) ∧ (¬EC(x) ∨ ¬GC(y) ∨ LessPollution(x, y))
PYQ Clone #3: "Exactly One" (Uniqueness) "There is exactly one student whose GPA is 4.0."
(Also: "Exactly one house in Parson costing Rs 20,00,000" / "Exactly one person with JEE rank 14")		 FOL: ∃x (S(x) ∧ GPA(x, 4.0) ∧ ∀y ((S(y) ∧ GPA(y, 4.0)) → (x = y)))
CNF (Skolem constant c): S(c) ∧ GPA(c, 4.0) ∧ (¬S(y) ∨ ¬GPA(y, 4.0) ∨ (y = c))
PYQ Clone #4: Superlative ("Any Other") "There is a restaurant in Paris that serves better food than any other restaurant in the city."
(Also: "House in Parson / Villa in Mumbai that costs more than any other...")		 FOL: ∃x (R(x) ∧ Paris(x) ∧ ∀y ((R(y) ∧ Paris(y) ∧ (y ≠ x)) → BetterFood(x, y)))
CNF (Skolem constant c): R(c) ∧ Paris(c) ∧ (¬R(y) ∨ ¬Paris(y) ∨ (y = c) ∨ BetterFood(c, y))
PYQ Clone #5: Universal + Nested Existential "A person who helps others is respected by everyone."
(Also: "A person who loves his mother is loved by everyone.")		 FOL: ∀x ((Person(x) ∧ ∃y (Person(y) ∧ Helps(x, y))) → ∀z (Person(z) → RespectedBy(z, x)))
CNF: ¬Person(x) ∨ ¬Person(y) ∨ ¬Helps(x, y) ∨ ¬Person(z) ∨ RespectedBy(z, x)

4.6 Quantified Inference Rules & Unification (MGU)

Topic 4.6
FOL Inference Rule Formal Rule Meaning & Restrictions
Universal Instantiation (UI) ∀v α   ∴   Subst({v/g}, α) Everyone → One: Replace universal variable v with any ground term g (e.g., x/Ravi).
Existential Instantiation (EI) ∃v α   ∴   Subst({v/k}, α) Someone → New Name: Replace existential variable v with a brand-new Skolem constant k not in KB.
Universal Generalization (UG) P(x) (arbitrary x)   ∴   ∀x P(x) Arbitrary one → Everyone: If proven for arbitrary x, holds for all x.
Existential Generalization (EG) P(c)   ∴   ∃x P(x) Known object → Someone exists: From Student(Ravi) infer ∃x Student(x).
3 Conditions for Unification — UNIFY(p, q) = θ:
1. Predicate symbols must be identical.   2. Number of arguments must be identical.
3. Variable Collision / Occurs Check: Cannot bind a variable to two different values in the same expression!
Expression p Expression q MGU (θ)
Knows(John, x) Knows(John, Jane) {x / Jane}
Knows(John, x) Knows(y, OJ) {y / John, x / OJ}
Knows(John, x) Knows(y, Mother(y)) {y / John, x / Mother(John)}
Knows(John, x) Knows(x, OJ) FAIL (x cannot be both John and OJ; must standardize apart first!)
Knows(John, x) Knows(y, z) {y / John, x / z} (Most General Unifier — least restrictive)

4.6 6-Step FOL-to-CNF Conversion Pipeline

Required for Resolution
Step Operation Transformation Rule / Example
Step 1 Eliminate Biconditionals (↔) Replace α ↔ β with (α → β) ∧ (β → α)
Step 2 Eliminate Implications (→) Replace α → β with ¬α ∨ β
Step 3 Move Negations (¬) Inward Apply De Morgan's Laws & Quantifier Negation:
¬∀x P(x) ⇒ ∃x ¬P(x)  |  ¬∃x P(x) ⇒ ∀x ¬P(x)
Step 4 Standardize Variables Apart Rename duplicate bound variables so each quantifier has its own unique variable: (∀x P(x)) ∨ (∀x Q(x)) ⇒ (∀x P(x)) ∨ (∀y Q(y))
Step 5 Skolemization (Eliminate ∃) • If ∃x is NOT inside any ∀: replace with Skolem Constant (∃x Student(x) ⇒ Student(c)).
• If ∃y IS inside ∀x: replace with Skolem Function (∀x ∃y LoyalTo(x,y) ⇒ LoyalTo(x, f(x))).
Step 6 Drop ∀ & Distribute ∨ over ∧ Remove all ∀ symbols and apply A ∨ (B ∧ C) ≡ (A ∨ B) ∧ (A ∨ C) to get clauses.
Slide Wumpus CNF Example: Convert B1,1 ↔ (P1,2 ∨ P2,1)
1. Elim ↔: (B1,1 → (P1,2 ∨ P2,1)) ∧ ((P1,2 ∨ P2,1) → B1,1)
2. Elim →: (¬B1,1 ∨ P1,2 ∨ P2,1) ∧ (¬(P1,2 ∨ P2,1) ∨ B1,1)
3. De Morgan: (¬B1,1 ∨ P1,2 ∨ P2,1) ∧ ((¬P1,2 ∧ ¬P2,1) ∨ B1,1)
4. Distribute: (¬B1,1 ∨ P1,2 ∨ P2,1) ∧ (¬P1,2 ∨ B1,1) ∧ (¬P2,1 ∨ B1,1)

4.7 Forward Chaining vs Backward Chaining

66.7% PYQ Probability
Horn Clause: Clause with at most one positive literal (e.g., ¬C ∨ ¬B ∨ A ≡ (C ∧ B) → A).
Definite Clause: Clause with exactly one positive literal (either a known Fact or a Rule Body → Head).
Generalized Modus Ponens (GMP): From p1', ..., pn' and (p1 ∧ ... ∧ pn → q) where p_i'θ = p_iθ, infer qθ.
Feature Forward Chaining (FC) Backward Chaining (BC)
Reasoning Style Data-Driven (Bottom-Up, Automatic) Goal-Driven (Top-Down, Query-Directed)
Direction Known Facts → Fire Rules → Add New Facts to WM Goal Query → Find matching Rule Head → Prove Body Subgoals
Search Strategy Breadth-first / iterative fixed-point (Linear time for Horn KB) Depth-first recursive proof search (Linear space in proof size)
Best Used For Monitoring, reactive agents, deriving all consequences Medical diagnosis, Prolog queries, proving a single target goal
Main Limitation Derives many irrelevant facts unrelated to the goal Can get stuck in infinite loops (must check goal stack & cache subgoals)

Slide Example: Colonel West Proof (FC & BC)

  • Facts: American(West), Missile(M1), Owns(Nono, M1), Enemy(Nono, America)
  • Rules: R1: American(x) ∧ Weapon(y) ∧ Sells(x,y,z) ∧ Hostile(z) → Criminal(x)
    R2: Missile(x) ∧ Owns(Nono, x) → Sells(West, x, Nono)
    R3: Missile(x) → Weapon(x)  |  R4: Enemy(x, America) → Hostile(x)
  • FC Iteration 1: Fire R3 → Weapon(M1); Fire R2 → Sells(West, M1, Nono); Fire R4 → Hostile(Nono).
  • FC Iteration 2: Fire R1 with {x/West, y/M1, z/Nono} → Criminal(West).

4.8 Resolution Refutation Proof Blueprint

83.3% PYQ Probability
Full FOL Resolution Rule: Given (l1 ∨ ... ∨ lk) and (m1 ∨ ... ∨ mn), if UNIFY(li, ¬mj) = θ, derive resolvent with li and mj cancelled and substitution θ applied.
5-Step Exam Format: 1. Translate English to FOL/PL → 2. Convert KB to CNF Clauses (C1..Cn) → 3. Add Negated Goal (¬Goal) → 4. Resolve pairs with Unification θ → 5. Reach Empty Clause (□ / ⊥).

Module 3 (3.4): Minimax & Alpha-Beta Pruning

10 Marks Guaranteed
Parameter Role & Initial Value Update & Pruning Rule
MAX Node (α) Best (highest) value found so far along path for MAX.
Initialize: α = -∞		 At MAX node: α = max(α, child_value).
Prune remaining children if α ≥ β (β-cutoff).
MIN Node (β) Best (lowest) value found so far along path for MIN.
Initialize: β = +∞		 At MIN node: β = min(β, child_value).
Prune remaining children if α ≥ β (α-cutoff).
3 Steps to Get 10/10 in Q1:
1. Propagate values bottom-up first (MIN takes minimum of children; MAX takes maximum) and state the optimal top move.
2. Pass (α, β) down to children; pass backed-up values up to update parent's α or β.
3. Explicitly list every pruned node and write the 1-line justification: "Node X is pruned because β (≤ value) ≤ α."
